# Twenty Palette Samples Implementation Plan

**Goal:** 기존 12색의 번호를 유지하며 20가지 키컬러와 각 색의 커버·추세 차트 샘플을 비교한다.

**Architecture:** 기존 `PALETTE_PREVIEWS`를 8개에서 20개로 늘리고 같은 내용의 입력 JSON 쌍을 추가한다. 원형 커버와 에디토리얼 차트의 레이아웃은 재사용한다. 비교판은 `out/`에만 생성한다.

**Tech Stack:** Python, Jinja, 기존 HTML/CSS/SVG, Playwright. 새 의존성 없음.

## 고정 조건

- 기존 01-12 번호: 버밀리언, 코랄, 앰버, 코퍼, 마젠타, 버건디, 바이올렛, 인디고, 애시드 라임, 포레스트 그린, 청록, 시안.
- 추가 13-20: 레드 #D7263D, 오렌지 #F0781E, 옐로 #EBCB20, 올리브 #718044, 민트 #21B889, UNIT 블루 #0064FF, 네이비 #183153, 슬레이트 #64748B.
- 커버 1440×756, 차트 1440×1200. 공식 흑백 로고, 워드마크 #0C1B33, 왼쪽 아래 날짜 #000000, SUIT 500/600/800, 안전 여백 6%를 유지한다.
- 후보 비교용 JSON만 추가한다. 기본 블루, 승인된 BTC 커버, 기존 8색의 내용·출력은 변경하지 않는다.
- 밝은 색의 데이터 선은 흰 배경 대비 3 이상, 작은 강조 텍스트는 4.5 이상인 같은 계열의 짙은 색을 사용한다.
- 예시 데이터 출처·기간·단위·범례를 유지한다. 색상 번호와 HEX는 비교판에서만 표시한다.
- 전체 20색 팔레트, 전체 샘플 한 장, 4색씩 다섯 비교판, 각 색의 개별 원본 PNG를 만든다.
- 커밋·푸시 및 다크 커버 재디자인은 범위 밖이다.

## 실행 체크리스트

- [x] `tests/test_palette_preview.py`의 기대 목록을 20색으로 늘린다. 기존 테스트로 40개 JSON, 색별 데이터 불변, 팔레트 대비와 입력 검증을 먼저 실패시킨다.
- [x] `render.py`의 팔레트 상수에 12개 항목만 추가한다. 기존 8개 값과 CSS·템플릿은 그대로 둔다.
- [x] `examples/previews/palettes/`에 24개 JSON을 추가하고 `docs/IMAGE_SYSTEM.md`에 전체 20색과 실행법을 기록한다.
- [x] `.venv/bin/python -m unittest discover -s tests -v`를 실행한다. 실제 40장을 렌더하고 기존 16장의 SHA-256이 유지되는지 확인한다.
- [x] 로컬 QA에서 날짜·로고 색, 안전 여백, 겹침, 제목 두 줄, 모든 후보의 동일 레이아웃, 원격 요청 부재를 확인한다. `sips`로 원본 규격을 확인한다.
- [x] 전체 팔레트와 비교판을 출력하고 원본·축소 이미지를 육안 검사한다.

## 검증 결과

- 전체 unittest 95개 통과. 추가 팔레트가 없을 때 예상된 실패를 먼저 확인했다.
- 40개 원본 PNG 규격 일치, 기존 16개 PNG SHA-256 동일.
- 40개 HTML의 가시적 텍스트 영역·날짜 검정·워드마크·단일 로고·SUIT·같은 레이아웃·색 대비 검사 통과. 렌더 검사에서 원격 요청 없음.
- `out/palette-20.png`: 1440×1200. `out/palette-samples-20.png`: 전체 20색 샘플. `out/palette-samples-01-04.png`부터 `17-20`까지 다섯 장의 확대 비교판.
- 모든 확대 비교판과 390px 차트 축소본을 열어 확인했다. 옐로 차트와 네이비 커버는 원본 크기로도 확인했다.
